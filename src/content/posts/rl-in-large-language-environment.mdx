## 一、引言：当 RL 遇上 LLM，旧的地图失效了

强化学习（Reinforcement Learning，RL）过去十年最辉煌的成就，几乎都发生在**封闭环境**里——围棋棋盘、Atari 游戏、机器人关节。这些环境有一个共同特点：状态空间是有限的（或至少是明确界定的），动作空间是固定的，奖励信号是即刻且确定的。

但大语言模型改变了这一切。

当 Agent 的动作不再是"落子在 (3, 4)"而是"生成一段代码"、"调用一个 API"、"修改一份计划书"时，动作空间从**离散有限**变成了**开放无限**。当环境不再是棋盘而是整个数字世界时，状态空间也随之爆炸。

温颖老师（上海交大长聘教轨副教授）在博见社的报告《大语言环境下的强化学习》，正是从这个前提切入，系统性地拆解了**当 RL 进入"大语言环境"（Large Language Environment, LLE）时，我们面临哪些全新的挑战，以及应该如何重新设计学习系统**。

## 二、石头剪刀布的陷阱：为什么"打败上一代"不等于进步

强化学习中有一个经典训练范式叫**自对弈（Self-play）**——让 Agent 不断和过去的自己对抗，在博弈中迭代变强。AlphaGo 就是这么练出来的。

但在大语言环境下，自对弈引入了一个被长期忽视的问题：

![零和博弈中的非传递性陷阱](/images/blog/report-rl-lle-1.jpg)

温颖老师用了一个非常直觉化的比喻——**石头剪刀布**。

在石头剪刀布中，剪刀赢布，布赢石头，石头赢剪刀。如果你训练一个 Agent 去"打败上一代自己"，它可能只是学会了克制上一代策略的特定弱点——而不是获得了普适性的策略提升。

**这叫做"非传递性陷阱"（Non-transitivity Trap）**。辛辛苦苦训练了一轮，Agent A 打败了 Agent B，Agent B 打败了 Agent C——但你回过头来测，Agent C 可能反过来打败了 Agent A。整个训练过程在策略空间中原地打转。

温颖老师的核心观点是：在 LLE 中做 RL，不能只看"单场胜利"，必须关注**群体层面的优化目标**。具体来说，在追求策略"提升"（Improvement）的同时，需要同时扩展策略的**多样性**（Diversity）和确保策略的**可传递性**（Transitivity）。这意味着训练框架需要覆盖更多有效策略的博弈空间，而不是在局部最优解附近反复震荡。

> 如果你对 RL 训练中梯度信号的传播机制还不熟悉，可以参考之前的文章[《梯度消失与梯度爆炸》](/blog/gradient-vanishing-exploding)了解基础——RL 的收敛性很大程度上依赖于稳定的梯度流，而非传递性恰恰会引入大量噪声梯度。

## 三、廉价生成，昂贵验证：LLM 时代的成本倒挂

这是全场最让我震撼的一张图——不是因为技术多复杂，而是因为它道出了一个被大多数人忽略的结构性变化：

![LLM 让生成变廉价，验证成为新瓶颈](/images/blog/report-rl-lle-2.jpg)

**在大模型出现之前，"生成方案"本身就很难。** 写一段代码、拟一份计划、想一个实验设计——这些都需要真正的人类专家投入时间。

**大模型改变了这个格局。** 现在，LLM 可以在几秒钟内生成 100 个不同的代码方案、50 种实验设计、20 个测试用例……"生成"这件事的边际成本趋近于零。

但问题随之而来：**你怎么从这 100 个方案中挑出那个真正正确的？**

温颖老师把这个问题归结为 RL 框架下的根本矛盾：

- **动作空间极大**（LLM 能做的事情太多了）
- **奖励信号不明**（哪个方案"对"，往往不是一眼能看出来的）
- **验证成本极高**（代码要跑通、方案要落地、结果要符合用户意图——每一步验证都需要真实世界的反馈）

在传统 RL 中，环境给出的奖励信号是明确的：棋子落在哪里、游戏得分多少、机械臂是否到达目标位置。但在 LLE 中，设计一个**高效、准确、成本可控的奖励模型**，本身就是当前 LLM-RL 领域最难的问题之一。

> **一句话总结**：LLM 把"生成"变成了白菜价，但"验证"依然是奢侈品。RL 的瓶颈从"怎么产生更多尝试"变成了"怎么判断哪次尝试是对的"。

## 四、EvoKernel：用真实硬件做"裁判"

理论聊完了，温颖老师用一个具体的实践案例展示了这个思路的威力——**EvoKernel**：

![EvoKernel——LLM + 真实硬件闭环的算子内核优化](/images/blog/report-rl-lle-3.jpg)

这是一个将大语言模型与**真实物理硬件**结合的 RL 闭环案例。目标很具体：为新型硬件（如 NPU）自动生成高性能的算子内核代码。这在实际工作中是一个极其耗时且依赖专家经验的任务，传统的做法是资深工程师手写和手动调优。

EvoKernel 的学习闭环是这样的：

1. **LLM 生成多种内核代码草案**（动作空间）——冷启动，不需要海量训练数据
2. **真实硬件编译**（验证语法）——能编译通过才算第一步
3. **正确性测试**（验证逻辑）——跑出来的结果对不对
4. **延迟剖析**（验证速度性能）——不仅要正确，还要比现有方案快
5. **记忆检索**——借鉴历史成功或失败的经验，注入下一轮生成

注意这个闭环的精妙之处：**每一步的反馈信号都是确定的、不可伪造的**。编译通过还是失败？测试跑通还是挂掉？延迟是多少纳秒？——这些都是硬件给出的客观事实，不存在"奖励模型不准"的困扰。

**结果验证了这个思路的有效性**：

- 代码**正确性从 11.0% 飙升到 83.0%**
- 执行速度**中位数提升 3.60 倍**
- 整个过程没有使用海量标注数据，完全靠环境反馈驱动学习

在上一篇文章[《Agent 架构全景》](/blog/agent-architecture-prompt-to-harness)中，我们讨论了 Harness Engineering——Agent 需要工程化的闭环来保障执行可靠性。而 EvoKernel 正是将**真实硬件环境**作为这个闭环的"裁判"——用确定性的编译结果和延迟数据替代了传统 RL 中那套模糊而昂贵的 reward model。

> **核心启示**：当你的环境能给出确定性的反馈信号时，RL 的高效性远超监督学习——哪怕你从只有 11% 正确率的冷启动开始。问题的关键不在于"模型够不够强"，而在于**"反馈够不够真"**。

## 五、大世界观：Agent 永远无法获知完全状态

讲完了实操，温颖老师把视角拉回理论层面，引入了一个我此前没有认真思考过的视角——**Rich Sutton 的"大世界观"**：

![大语言环境——无限、无边界、部分可观察的大世界](/images/blog/report-rl-lle-4.jpg)

Rich Sutton 是强化学习领域泰斗级人物（"The Bitter Lesson"的作者）。他的"大世界观"对 LLE 下的 RL 有三个基本判断：

### 1. 无法获知完全状态

大语言环境包含外部真实世界、运行时环境、Agent 的内在推理空间、证据反馈链接，甚至还包括 Agent 自身的更新机制（知识库、上下文、记忆、模型权重）。整个系统的复杂度（World complexity）远远超过单个 Agent 的感知能力（Agent capacity）。你永远只能看到世界的一小部分。

### 2. 无法表示最优策略

在围棋棋盘上，理论上存在"最优解"——即使它远超人类的计算能力，但数学上它是存在的。但在 LLE 中，由于环境无边无际、任务千变万化，**很多场景下根本不存在"最优策略"，只有不断逼近的近似解**。

### 3. 必须学习近似的接口

这意味着做 LLE-RL 必须放弃传统的"全知全能环境"假设。你不能指望环境给你一套干净、完整、结构化的状态表示。你必须**学习一个近似的接口**——一个能帮你在这个无限世界中捕捉关键信号的简化模型。

> 温颖老师的总结非常精炼：**在大语言环境下做 RL，必须寻找节俭而高效的方法，在无边界的世界中学习有用的策略接口。**

## 六、范式转变：Agent 不仅要行动，还要"写回自身"

如果前几张图讲的是"问题"和"实践"，那最后这张图直指**底层范式的根本差异**：

![传统 RL 环境 vs 大语言环境——核心范式差异](/images/blog/report-rl-lle-5.jpg)

传统 RL 环境（如游戏、机器人）的特点是：**封闭接口、固定环境、只可写回外部状态**。Agent 的动作只能改变外部环境——按下按钮、移动棋子、旋转关节。环境反馈立即给出奖励，Agent 需要学习的就是一个决策策略 π。

而大语言环境（LLE）完全不同：**开放接口、动态世界、具有风险的可写回自身**。

**最关键的差异在于"谁构建了学习接口"**：

在 LLE 中，Agent 不仅能采取外部动作（调用 API、生成代码、发送消息），更重要的是——**它必须学会将经验"写回"到 Agent 自身**。它不仅更新外部状态，还要更新自己的**上下文记忆、技能库、行为规则，甚至是底层模型权重**。

这意味着什么？

> 大语言环境下的强化学习，本质上是在无边界的动态世界中，**构建一个能够自我反省、自我更新、自我进化的开放系统**。

这不只是做决策，而是在**构建一个能不断改进自身决策框架的元系统**。

把这一点和上一篇文章中张航帆老师提出的 Self-Harness 框架联系起来看——两者从不同角度（RL 理论 vs 工程实践）指向了同一个结论：**Agent 的长期竞争力不在于初始有多"聪明"，而在于它有多擅长从经验中重塑自己。**

## 七、总结：三个范式转变

温颖老师的报告可以提炼为**三个范式转变**：

1. **从"追求最优"到"追求多样"**：在 LLE 的零和博弈中，打败上一代自己不等于进步。需要同时关注策略提升、多样性和可传递性——否则训练只会在局部策略空间里原地打转。

2. **从"奖励驱动"到"验证驱动"**：LLM 让生成方案变得廉价，但验证依然昂贵。EvoKernel 的成功证明，当一个环境能提供确定性的验证信号（编译通过/失败、延迟多少纳秒），RL 的效率远超监督学习——从 11% 正确率冷启动到 83%。

3. **从"学决策"到"学进化"**：传统 RL 的终点是学会一个好的策略 π。但在 LLE 中，Agent 必须学会**如何构建和改进自己的学习接口**——把经验写回自身，在不断变化的环境中持续进化。

这三点放在一起，实际上提出了一个非常前沿的观点：

> **在 LLM + RL 的框架下，我们不需要追求一个全知全能的 Agent，而是要构建一个能"低门槛生成方案，硬核环境快速验证，失败经验写回自身"的动态进化系统。**

验证的昂贵、环境的无限、自我更新接口的构建——正是当下 AI 智能体走向真实世界需要解决的核心难题。
