## 一、引言

我们生活在一个数据爆炸的时代——社交媒体、电商交易、传感器网络、日志系统，每天都在产生 PB 级别的数据。单台机器的存储和计算能力早已捉襟见肘，**分布式计算**成为处理海量数据的必然选择。

在开源大数据生态中，**Hadoop** 毫无疑问是最具影响力的项目之一。几乎所有主流厂商——谷歌、雅虎、微软、思科、淘宝——都围绕 Hadoop 提供开发工具和技术服务。它从 Google 的两篇论文（GFS 和 MapReduce）获得灵感，将分布式存储与计算的复杂性封装为普通开发者也能上手的工具。

本文是我学习《大数据技术》课程中 Hadoop 与 HDFS 的实验笔记，涵盖概念原理、环境搭建、命令行操作和 Python 编程四部分，适合跟我一样刚入门大数据的朋友参考。

## 二、Hadoop 概述

### Hadoop 是什么

Hadoop 是 Apache 软件基金会旗下的一个**开源分布式计算平台**，基于 Java 语言开发，具有很好的跨平台特性，可以部署在廉价的计算机集群中。它为用户提供了系统底层细节透明的分布式基础架构——开发者不需要关心数据存在哪台机器、怎么分片、如何容错，Hadoop 帮你搞定这一切。

它的核心是两大组件：

- **HDFS**（Hadoop Distributed File System）—— 分布式文件系统，负责海量数据的存储
- **MapReduce** —— 分布式计算模型，负责对存储在 HDFS 上的数据进行并行处理

你可以把它理解为一个"超级仓库 + 流水线工厂"：HDFS 是仓库，把数据分散存放在多台机器上；MapReduce 是流水线，同时调度多台机器并行处理数据。Hadoop 被公认为行业大数据标准开源软件，在分布式环境下提供了海量数据的处理能力。

### 历史发展

Hadoop 的发展历程是一段精彩的开源传奇：

| 时间 | 事件 |
|------|------|
| 2002 年 | Apache Nutch 项目启动，由 Lucene 创始人 Doug Cutting 主导开发 |
| 2004 年 | Nutch 模仿 Google GFS 论文，开发了分布式文件系统 **NDFS**（即 HDFS 前身） |
| 2004 年 | Google 发表 MapReduce 论文，阐述分布式编程思想 |
| 2005 年 | Nutch 开源实现了 Google 的 MapReduce |
| 2006 年 | 分布式存储与计算部分从 Nutch 独立，正式命名为 Hadoop |
| 2008 年 1 月 | Hadoop 正式成为 Apache 顶级项目 |
| 2008 年 4 月 | Hadoop 打破世界纪录：**910 个节点集群，1TB 数据排序仅用 209 秒** |
| 2009 年 5 月 | 1TB 数据排序时间缩短到 **62 秒**，从此名震业界 |

Hadoop 从此迅速发展，成为大数据时代最具影响力的开源分布式开发平台，并成为事实上的大数据处理标准。

### 核心特性

Hadoop 具有以下几个方面的特性：

| 特性 | 说明 |
|------|------|
| **高可靠性** | 数据默认保存多个副本，节点故障时自动恢复 |
| **高效性** | 数据在节点间并行处理，就近读取，减少网络开销 |
| **高可扩展性** | 可扩展到数千个节点，动态增加机器无需停机 |
| **高容错性** | 自动检测节点故障，将失败任务重新分配到健康节点 |
| **成本低** | 运行在普通商用服务器上即可，不需要昂贵硬件 |
| **运行在 Linux 平台** | 以 Linux 为主要运行环境，充分发挥集群性能 |
| **支持多种编程语言** | 除 Java 外，也支持 Python 等语言通过接口访问 |

### Hadoop 生态架构

Hadoop 早已不只是一个存储+计算的工具，围绕它形成了完整的生态体系。课件中将其分为三个层次：

```text
Hadoop 生态
│
├── 数据采集层
│   ├── Flume         ← 日志采集、聚合与传输
│   └── Sqoop         ← 关系数据库与 Hadoop 之间的数据导入导出
│
├── 数据存储层
│   ├── HDFS          ← 分布式文件系统（核心存储）
│   └── HBase         ← 分布式 NoSQL 数据库（几十亿行 × 上百万列），支持随机读写和实时应用
│
├── 数据计算层
│   ├── MapReduce     ← 分布式离线计算框架，数据挖掘/机器学习/商务智能的算法基础
│   ├── YARN          ← 资源管理与作业调度
│   ├── Spark         ← 内存计算引擎（比 MapReduce 快 10-100 倍）
│   ├── Hive          ← 数据仓库，支持 SQL 查询语句
│   ├── Pig           ← 轻量级脚本语言，实现流式数据处理
│   └── Storm         ← 实时流计算
│
├── 协调与管理层
│   ├── ZooKeeper     ← 分布式协调服务
│   └── Ambari        ← 集群部署、管理与监控
│
└── 访问接口层
    ├── Shell         ← 命令行操作
    └── API           ← 编程接口（Java / Python 等）
```

本文聚焦在生态的存储基石——**HDFS**。

## 三、HDFS 分布式文件系统

### 设计目标与局限性

HDFS 的设计目标非常明确：

- **存储海量数据**：支持 GB、TB 甚至 PB 级别的文件
- **只追加，不修改**：文件一旦写入，不支持随机修改，只能在末尾追加数据
- **顺序读写优先**：优化大文件的顺序 I/O，不擅长随机读写小文件
- **高吞吐而非低延迟**：设计重点是单位时间处理更多数据，而非单次请求快速响应

但 HDFS 也有其**局限性**：
- 不适合低延迟的数据访问（如毫秒级响应）
- 无法高效存储大量小文件（每个小文件都占用一个 block，元数据膨胀）
- 不支持多用户同时写入同一文件，也不支持在文件任意位置修改

一句话概括：HDFS 是为"把海量数据一次性写入、多次顺序读出来做分析"这个场景设计的，而不是用来做实时查询或频繁修改的。

### 架构组件

HDFS 采用 **Master/Slave** 主从架构，由**两大组件**——名称节点和数据节点——构成：

```text
                    ┌──────────────┐
                    │   NameNode   │  ← 主节点（Master）
                    │  （元数据管理） │    管理文件目录树、block 映射表
                    └──────┬───────┘
                           │ 心跳 + 块报告（运行中不断沟通，实时维护信息）
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ DataNode │ │ DataNode │ │ DataNode │  ← 从节点（Slaves）
        │ （数据存储）│ │ （数据存储）│ │ （数据存储）│    实际存储文件 block
        └──────────┘ └──────────┘ └──────────┘
```

#### NameNode（名称节点）

NameNode 是整个 HDFS 的**大脑**。它存储了所有文件和目录的**元数据**（Metadata）：

- 文件系统的目录树结构
- 每个文件被切分成了哪些 block
- 每个 block 分布在哪些 DataNode 上

这些元数据保存在内存中（`FsImage` + `EditLog`），所以 NameNode 对内存要求较高。**NameNode 本身不存储实际数据**——它只告诉你"文件在哪里"。在运行过程中，DataNode 与 NameNode 不断沟通，实时维护集群状态信息。

#### DataNode（数据节点）

DataNode 是**干活的工人**，负责实际存储文件的数据块（block）。每个 DataNode 会定期向 NameNode 发送**心跳**（默认每 3 秒），报告自己还活着；同时发送**块报告**，告知自己存储了哪些 block。

#### Secondary NameNode（第二名称节点）

别被名字误导——Secondary NameNode **不是 NameNode 的热备份**。它的作用是定期合并 `FsImage`（命名空间快照）和 `EditLog`（操作日志），防止 EditLog 过大导致下次 NameNode 启动时间过长。

### 核心机制

#### 数据冗余保存

HDFS 默认将每个 block 保存 **多个副本**（replication factor 可配置），分布在不同 DataNode 上。如果一台机器挂了，系统会自动从其他副本恢复。

副本放置策略：第一个副本放在本机（如果客户端在集群内），第二个放在不同机架，第三个放在同一机架的不同节点上——兼顾了可靠性和网络效率。

#### 数据块存储

HDFS 将大文件切分成固定大小的 **block** 进行存储（Hadoop 2.x 默认 128MB）。切块有两个好处：

1. 一个大文件的不同 block 可以分散到不同节点的磁盘上，实现**并行读写**
2. block 大小远大于普通文件系统的 block（约几千字节），大大减少了寻址开销

```text
文件 mydata.log (300MB)
     │
     ├── block_001 (128MB) → DataNode A, DataNode C, DataNode E
     ├── block_002 (128MB) → DataNode B, DataNode A, DataNode D
     └── block_003 ( 44MB) → DataNode C, DataNode B, DataNode E
```

#### 数据读取策略

HDFS 读取数据时，会按照"就近原则"优先从离客户端最近的 DataNode 读取数据，以最大化吞吐量和减少网络延迟。数据读取支持 checksum 校验，确保数据完整性。

#### 错误检测与恢复

- **DataNode 故障**：NameNode 收不到心跳（默认 10 分钟超时），将该节点标记为失效，自动触发副本复制以保证副本数达标
- **数据校验**：客户端读取数据时，HDFS 通过校验和（checksum）验证数据完整性
- **NameNode 单点故障**：Hadoop 2.x 引入 **HA（高可用）机制**，通过一对 NameNode（Active + Standby）和共享的 JournalNode 实现故障自动切换

### 读写流程

#### 读操作流程

1. 客户端向 NameNode 请求读取文件
2. NameNode 返回该文件所有 block 所在的 DataNode 列表（按与客户端距离排序）
3. 客户端从最近的 DataNode 读取 block，每个 block 读取完成后校验 checksum
4. 如果当前 DataNode 读取失败，自动尝试列表中下一个 DataNode

```text
客户端 → NameNode: "我要读 /user/merrain/file.log"
客户端 ← NameNode: "block_001 在 DN-A, DN-C; block_002 在 DN-B, DN-A..."
客户端 → DN-A: 读取 block_001（校验通过）
客户端 → DN-B: 读取 block_002（校验通过）
```

#### 写操作流程

1. 客户端向 NameNode 请求写入文件
2. NameNode 检查文件是否已存在、客户端是否有写权限，通过后返回一组 DataNode 地址
3. 客户端将数据写入第一个 DataNode，该 DataNode 将数据通过**流水线（pipeline）**转发给第二个，第二个再转发给第三个
4. 每个 block 写入完成后，确认消息沿流水线反向传回
5. 全部 block 写入完成后，客户端通知 NameNode 关闭文件

```text
客户端 → NameNode: "我要写 /user/merrain/new.log"
客户端 ← NameNode: "写入 DN-A → DN-C → DN-E"
客户端 → DN-A → DN-C → DN-E: 数据流水线写入
DN-E → DN-C → DN-A → 客户端: block_001 写入完成确认
```

### 通信协议

HDFS 的节点间通信基于 TCP/IP，主要使用三种协议：

| 协议 | 用途 |
|------|------|
| **客户端协议** | 客户端与 NameNode 之间的通信（文件元数据操作） |
| **数据节点协议** | 客户端与 DataNode、DataNode 之间的实际数据传输 |
| **远程过程调用（RPC）** | NameNode 与 DataNode 之间的管理指令通信 |

访问 HDFS 的方式主要有两种：**Shell 命令行**和 **API 编程接口**。

## 四、实验环境搭建与配置

以下实验步骤来自课程实际操作，环境为 Ubuntu 系统。用户名统一使用 `merrain`。

### SSH 安装与免密登录

Hadoop 启动/停止脚本需要通过 SSH 在各节点间执行命令。如果没有 SSH，登录 HDFS 将会失败。

```bash
# 1. 安装 SSH（提示时选择 Y）
sudo apt install openssh-server openssh-client -y

# 2. 创建 .ssh 目录并进入
mkdir ~/.ssh && cd ~/.ssh

# 3. 生成 SSH 密钥（一路回车，不设密码）
ssh-keygen -t rsa -P "" -f ~/.ssh/id_rsa

# 4. 将公钥加入授权列表
cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys

# 5. 验证免密登录
ssh localhost
```

### Java 环境安装

Hadoop 是基于 Java 开发的，必须先安装 JDK（课程使用 jdk1.8.0_162）：

```bash
# 1. 进入下载目录，查看下载好的文件
cd ~/下载
ls

# 2. 创建 JVM 目录，解压 JDK
sudo mkdir -p /usr/lib/jvm
sudo tar -zxf jdk-8u162-linux-x64.tar.gz -C /usr/lib/jvm/

# 3. 回到家目录，编辑 .bashrc 配置环境变量
cd ~
vim ~/.bashrc

# 4. 添加以下内容：
export JAVA_HOME=/usr/lib/jvm/jdk1.8.0_162
export JRE_HOME=${JAVA_HOME}/jre
export CLASSPATH=.:${JAVA_HOME}/lib:${JRE_HOME}/lib
export PATH=${JAVA_HOME}/bin:$PATH

# 5. 使环境变量生效
source ~/.bashrc

# 6. 验证安装
java -version
```

### Hadoop 安装与配置

```bash
# 1. 解压 Hadoop 到 /usr/local
sudo tar -zxf hadoop-3.3.6.tar.gz -C /usr/local/

# 2. 进入目录，重命名并修改权限
cd /usr/local
sudo mv hadoop-3.3.6 hadoop

# 3. 进入 hadoop 目录查看内容
cd hadoop
ls

# 4. 配置 Hadoop 环境变量
vim ~/.bashrc

# 添加以下内容：

export PATH=$PATH:$HADOOP_HOME/bin
export PATH=$PATH:$HADOOP_HOME/sbin

# 5. 生效并验证
source ~/.bashrc

```

### 配置核心文件

进入 Hadoop 配置目录，编辑配置文件。**注意**：课件中将所有配置合并在一个文件中以便教学，实际生产环境应将属性分别放入 `core-site.xml` 和 `hdfs-site.xml`。

```bash
cd /usr/local/hadoop/etc/hadoop
vim core-site.xml
```

将以下属性写入 `<configuration>` 标签内：

```xml
<property>
    <name>hadoop.tmp.dir</name>
    <value>file:/usr/local/hadoop/tmp</value>
    <description>临时文件目录，NameNode 和 DataNode 数据也存这里</description>
</property>
<property>
    <name>fs.defaultFS</name>
    <value>hdfs://localhost:9000</value>
    <description>HDFS 默认文件系统地址</description>
</property>
<property>
    <name>dfs.replication</name>
    <value>1</value>
    <description>副本数。单机伪分布式设为 1</description>
</property>
<property>
    <name>dfs.namenode.name.dir</name>
    <value>file:/usr/local/hadoop/tmp/dfs/name</value>
    <description>NameNode 元数据存储路径</description>
</property>
<property>
    <name>dfs.datanode.data.dir</name>
    <value>file:/usr/local/hadoop/tmp/dfs/data</value>
    <description>DataNode 数据存储路径</description>
</property>
<property>
    <name>hadoop.http.staticuser.user</name>
    <value>merrain</value>
    <description>Web 界面静态用户，设为当前用户名</description>
</property>
```

> **说明**：`hadoop.http.staticuser.user` 设为 `merrain` 后，通过 Web 界面浏览 HDFS 文件时将以 merrain 用户身份访问，否则可能因权限问题无法查看文件。

## 五、HDFS 基本操作（命令行）

启动 HDFS 服务后，使用 `hdfs dfs` 命令操作文件系统。注意：必须先配置好环境变量（`HADOOP_HOME` 和 `PATH`），才可在任意位置执行以下命令。`.` 表示当前用户在 HDFS 上的家目录。

### 基础命令一览

```bash
# === 查看与创建 ===

# 查看 HDFS 根目录（首次为空）
hdfs dfs -ls /

# 为当前用户创建家目录
hdfs dfs -mkdir -p /user/merrain

# 再次查看，出现新建的目录
hdfs dfs -ls /

# 在家目录下创建 input 子目录
hdfs dfs -mkdir /user/merrain/input

# 查看家目录（以下两种方式等价）
hdfs dfs -ls /user/merrain
hdfs dfs -ls .                        # '.' 表示当前用户家目录

# === 上传文件 ===

# 先在 Linux 本地创建测试文件
echo "Hello Hadoop!" > ~/localfile.txt

# 上传文件到 HDFS
hdfs dfs -put ~/localfile.txt /user/merrain/input/

# 查看上传结果
hdfs dfs -ls /user/merrain/input/

# 查看文件内容
hdfs dfs -cat /user/merrain/input/localfile.txt

# === 下载文件 ===

# 查看本地家目录（确认没有该文件）
ls ~/localfile.txt            # 报错：文件不存在

# 从 HDFS 下载文件到 Linux 本地
hdfs dfs -get /user/merrain/input/localfile.txt ~/

# 也可下载到新建目录
mkdir ~/newdir
hdfs dfs -get /user/merrain/input/localfile.txt ~/newdir/

# 查看下载结果
cat ~/newdir/localfile.txt

# === 目录间拷贝 ===

# 在 HDFS 根目录下创建新目录
hdfs dfs -mkdir /test

# 在不同目录间拷贝文件
hdfs dfs -cp /user/merrain/input/localfile.txt /test/

# 查看拷贝结果
hdfs dfs -ls /test/

# === 其他操作 ===

# 查看文件信息（文件名、大小、副本数）
hdfs dfs -stat "%n %b %r" /user/merrain/input/localfile.txt

# 查看磁盘使用情况
hdfs dfs -du -h /user/merrain/
hdfs dfs -df -h                    # HDFS 整体空间

# 删除文件
hdfs dfs -rm /user/merrain/input/localfile.txt

# 递归删除目录
hdfs dfs -rm -r /test

# 追加内容到已有文件
hdfs dfs -appendToFile ~/追加内容.txt /user/merrain/input/已有文件.txt
```

> **注意**：如果遇到 `Connection refused` 错误，说明 HDFS 服务未启动，执行 `start-dfs.sh` 重新启动即可。

### Web 界面

启动 HDFS 后，打开浏览器访问 NameNode 的 Web 管理界面：

```text
http://localhost:9870
```

在这个界面中可以浏览文件系统、查看 DataNode 状态、下载文件、检查日志等。生产环境中这是运维人员日常使用的入口。

## 六、HDFS 编程实践

掌握了命令行操作后，我们用 Python 来完成一个实际的编程任务。

### 实践题目

假设在目录 `hdfs://localhost:9000/user/merrain` 下有几个文件：`file1.txt`、`file2.txt`、`file3.txt`、`file4.abc` 和 `file5.abc`。需要完成以下任务：

1. 过滤出所有**后缀名不为 `.abc`** 的文件
2. 读取这些文件的内容
3. 将所有内容合并，写入文件 `hdfs://localhost:9000/user/merrain/merge.txt`

### 环境准备

```bash
# 安装 pip（如未安装）
sudo apt install python3-pip -y

# 安装 hdfs 包
pip install hdfs
```

`hdfs` 包封装了 HDFS 的 WebHDFS REST API，无需在客户端安装 Hadoop 即可远程操作 HDFS。

### 完整实现代码

```python
from hdfs import InsecureClient

# 连接 HDFS
client = InsecureClient('http://localhost:9870', user='merrain')

# 目标目录
target_dir = '/user/merrain'

# 列出目录下所有文件，过滤出后缀不为 .abc 的文件
all_files = client.list(target_dir)
filtered_files = [f for f in all_files if not f.endswith('.abc')]

print(f"目录中的所有文件: {all_files}")
print(f"过滤后的文件: {filtered_files}")

# 读取过滤后的文件内容并合并
merged_content = ''
for filename in filtered_files:
    file_path = f'{target_dir}/{filename}'
    with client.read(file_path, encoding='utf-8') as reader:
        content = reader.read()
        merged_content += content + '\n'
        print(f"已读取: {filename}")

# 将合并后的内容写入新文件
merge_path = f'{target_dir}/merge.txt'
client.write(merge_path, merged_content, encoding='utf-8', overwrite=True)

print(f"合并完成！输出文件: {merge_path}")

# 验证：读取合并后的文件
with client.read(merge_path, encoding='utf-8') as reader:
    print(f"\n=== merge.txt 内容 ===\n{reader.read()}")
```

### Python Unicode 编码说明

课件中特别强调了编码问题，这是一个初学者容易踩的坑：

Python 3 的字符串类型（`str`）在内存中以 **Unicode** 表示——一个字符对应若干字节。当我们需要在网络上传输数据或保存到磁盘时，必须把 `str` 变成以字节为单位的 `bytes`。

`hdfs` 包在读写文件时自动处理了 `str → bytes` 的转换（默认使用 UTF-8 编码），这意味着大多数情况下我们不需要关心底层细节。但当遇到非 UTF-8 编码的文件时（比如 Windows 上生成的 GBK 编码文件），就需要显式处理：

```python
# 情况 1：文件是 UTF-8 编码（最常见，hdfs 包默认处理）
with client.read('/user/merrain/input/data.txt', encoding='utf-8') as reader:
    content = reader.read()

# 情况 2：文件是 GBK 编码（如来自 Windows 系统的文件）
with client.read('/user/merrain/input/data.txt') as reader:
    raw_bytes = reader.read()                     # 先读取原始字节
    content = raw_bytes.decode('gbk', errors='replace')  # 再用 GBK 解码
```

核心原则：**先搞清楚文件的编码格式，再用对应的编码去读取。**
