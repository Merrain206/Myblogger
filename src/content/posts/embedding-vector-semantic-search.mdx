## 一、机器如何"理解"文字？

人类看到"苹果"这个词，脑海中会浮现出红色的果实、酸甜的口感、甚至牛顿和 iPhone。但计算机看到的只是一串字符——一堆 ASCII 或 Unicode 编码，没有任何语义信息。

要让机器处理自然语言，我们需要一种**数学表示**，把文字映射成机器能计算的数学对象。这个映射，就是 **Embedding**。

Embedding 的核心思想可以浓缩为一句话：

> **将离散的符号（词、句子、文档）映射为稠密的实数向量，使得语义相近的文本在向量空间中距离也相近。**

这篇文章从三个层面展开：**Embedding 的映射原理**（怎么从离散到稠密）、**Embedding 在系统中的角色**（文本的向量化表示）、以及**检索流程**（向量相似度检索是如何工作的）。

## 二、Embedding 映射：从离散到稠密

### 2.1 独热编码：最简单的起点

假设我们的词汇表只有 5 个词：`["我", "爱", "苹果", "香蕉", "深度学习"]`。

最直接的表示方式是**独热编码（One-Hot Encoding）**：每个词分配一个维度，该词对应的位置为 1，其余为 0。

```
"苹果"   → [0, 0, 1, 0, 0]
"香蕉"   → [0, 0, 0, 1, 0]
"深度学习" → [0, 0, 0, 0, 1]
```

这看起来很直观，但问题重重：

1. **维度灾难**：词汇表有多大，向量就有多少维（通常几十万到几百万维）。
2. **语义黑洞**：任意两个词的余弦相似度都是 0——"苹果"和"香蕉"在独热编码看来，和"苹果"与"深度学习"一样不相关。
3. **无法泛化**：新词出现时向量维度不够用。

### 2.2 分布式表示：用稠密向量捕捉语义

**分布式表示（Distributed Representation）** 是 Embedding 的理论基石。它的核心假设是：

> 一个词的含义由它周围的上下文决定（Distributional Hypothesis）。

与其用"第几个词是 1"，不如给每个词分配一个**低维稠密向量**，让模型在训练过程中自行学习每个维度的含义。比如：

```
"苹果"   → [0.23, -0.71, 0.45, 0.12, ...]  (768维)
"香蕉"   → [0.19, -0.68, 0.41, 0.15, ...]  (768维)
"深度学习" → [0.87, 0.32, -0.53, -0.21, ...] (768维)
```

注意看：**"苹果"和"香蕉"的向量在前几个维度上很接近**——因为它们在语料中经常出现在类似的上下文中（"吃____"、"____很好吃"）。而"深度学习"的向量则截然不同。

这种稠密向量的维度通常在 128 到 4096 之间，远小于词表大小，却**压缩了海量的语义信息**。

### 2.3 从 Word2Vec 到现代 Embedding 模型

**Word2Vec (2013)** 是最具里程碑意义的词嵌入方法。它用浅层神经网络，通过两种训练模式学习词向量：

- **CBOW（Continuous Bag of Words）**：用上下文词预测目标词
- **Skip-gram**：用目标词预测上下文词

```python
# Word2Vec 的核心思想（简化示意）
# Skip-gram: 给定"苹果"，预测其上下文["吃", "一个", "很", "好吃"]
# 模型被迫学习：什么样的向量，能最好地预测出这些上下文词？
```

训练完成后，神奇的事情发生了。通过向量运算，模型展现出了**语义推理**能力：

$$
\text{Vec}(\text{国王}) - \text{Vec}(\text{男人}) + \text{Vec}(\text{女人}) \approx \text{Vec}(\text{王后})
$$

$$
\text{Vec}(\text{北京}) - \text{Vec}(\text{中国}) + \text{Vec}(\text{法国}) \approx \text{Vec}(\text{巴黎})
$$

这揭示了 Embedding 的本质：**向量空间中的方向编码了语义关系**。

随后出现了 **GloVe**（基于全局词共现矩阵）、**FastText**（引入子词信息），再到基于 Transformer 的 **BERT**、**Sentence-BERT**，以及 OpenAI 的 **text-embedding-3** 系列——Embedding 从"词"级别进化到了"句子"和"段落"级别。

### 2.4 映射函数：$f: \text{文本} \rightarrow \mathbb{R}^d$

从数学角度看，Embedding 模型就是一个映射函数：

$$
f_\theta: \mathcal{X} \rightarrow \mathbb{R}^d
$$

其中：
- $\mathcal{X}$ 是文本空间（任意长度字符串）
- $\mathbb{R}^d$ 是 $d$ 维实数向量空间
- $\theta$ 是模型的参数（通过训练得到）

这个函数的核心约束是：**语义相似度在向量空间中体现为几何距离**。

$$
\text{sim}(A, B) \propto \frac{1}{\text{dist}(f_\theta(A), f_\theta(B))}
$$

## 三、Embedding 的角色：文本的向量化表示

在一个现代 NLP 系统中，Embedding 扮演的是**桥梁**角色——它是文本世界和数学世界之间的翻译官。

### 3.1 作为"语义坐标"

想象一个巨大的语义空间。每个文档、每个查询、每段对话，都在这个空间中有一个坐标：

```
搜索查询："如何在 PyTorch 中训练一个 Transformer"
    ↓ Embedding 模型
向量坐标：[0.12, -0.43, 0.78, ..., 0.05]  (1536维)
```

这个坐标不是随机的——它跟所有语义相关的文档**彼此靠近**。这就是为什么你能在搜索引擎中输入自然语言，而不是精确关键词。

### 3.2 三种 Embedding 层次

| 层次 | 粒度 | 典型模型 | 应用场景 |
|------|------|----------|----------|
| **词级** | 单个词/Token | Word2Vec, GloVe | 词义分析、同义词发现 |
| **句级** | 句子/段落 | Sentence-BERT | 语义搜索、文本聚类 |
| **文档级** | 整篇文章 | text-embedding-3-large | RAG 检索、文档去重 |

在 RAG（检索增强生成）系统中，通常使用**句级或段落级 Embedding**，因为：
1. 整篇文章太长，Embedding 模型有最大 token 限制
2. 检索的目标是找到"相关片段"而非整篇文档
3. 片段级检索更精确，能定位到具体段落

### 3.3 Embedding 质量的关键指标

如何判断一个 Embedding 好不好？常用评估标准包括：

- **语义相似度保持性**：同类文本的向量距离是否确实更近？
- **检索召回率（Recall@K）**：在 Top-K 结果中，有多少是真正相关的？
- **MTEB 基准**（Massive Text Embedding Benchmark）：覆盖分类、聚类、配对、检索、摘要等多种任务的综合评估。

```python
# 评估 Embedding 质量的核心逻辑（伪代码）
def evaluate_embedding(model, test_pairs):
    """test_pairs: [(query, relevant_doc, irrelevant_doc), ...]"""
    correct = 0
    for query, relevant, irrelevant in test_pairs:
        q_vec = model.encode(query)
        rel_vec = model.encode(relevant)
        irr_vec = model.encode(irrelevant)
        if cosine_sim(q_vec, rel_vec) > cosine_sim(q_vec, irr_vec):
            correct += 1
    return correct / len(test_pairs)
```

## 四、检索流程：向量相似度检索

有了优质 Embedding，接下来就是**检索**——在海量向量中，快速找到与查询最相似的那些。

### 4.1 从关键词匹配到语义检索

传统搜索依赖关键词匹配：

```
查询："怎么学深度学习"
    ↓ 关键词分词
["怎么", "学", "深度学习"]
    ↓ 倒排索引匹配
结果：包含这些词的文章（可能漏掉"机器学习入门指南"）
```

向量检索则完全不同：

```
查询："怎么学深度学习"
    ↓ Embedding 模型
向量：0x3A2F...
    ↓ 相似度计算
结果：语义相关的所有文档（包括"机器学习入门指南"、"神经网络教程"）
```

**关键差异**：向量检索理解了"深度学习"和"神经网络"是相关概念，即使查询中没有出现"神经网络"这个词。

### 4.2 余弦相似度：衡量向量间的"亲疏"

最常用的相似度度量是**余弦相似度（Cosine Similarity）**：

$$
\text{cosine\_sim}(\mathbf{a}, \mathbf{b}) = \frac{\mathbf{a} \cdot \mathbf{b}}{||\mathbf{a}|| \cdot ||\mathbf{b}||} = \frac{\sum_{i=1}^{d} a_i b_i}{\sqrt{\sum_{i=1}^{d} a_i^2} \cdot \sqrt{\sum_{i=1}^{d} b_i^2}}
$$

它衡量的是两个向量**方向的接近程度**，取值在 $[-1, 1]$ 之间：
- $1$：方向完全一致
- $0$：正交（无关）
- $-1$：方向完全相反

在 Embedding 检索中，通常只关注正值（$0$ 到 $1$），越接近 $1$ 越相关。

### 4.3 向量数据库与近似最近邻搜索

当数据量达到百万、亿级别，逐条计算余弦相似度（暴力搜索）就不可接受了。这时候需要**近似最近邻（ANN）搜索**。

核心思路：**用精度换速度**，放弃"绝对找到最相似的 Top-K"，改为"几乎找到最相似的 Top-K"。

主流 ANN 算法：

| 算法 | 思路 | 代表库 |
|------|------|--------|
| **LSH** | 哈希到相近桶中 | —— |
| **IVF** | 先聚类再搜索 | Faiss |
| **HNSW** | 多层可导航小世界图 | Faiss, pgvector |
| **PQ** | 乘积量化压缩向量 | Faiss |

现代向量数据库（Milvus、Pinecone、Weaviate、Qdrant、pgvector）将这些算法封装成了易用的服务。

```python
# 使用 Faiss 构建向量索引（示意）
import faiss
import numpy as np

# 假设有 100 万条 768 维的文档向量
doc_vectors = np.random.randn(1_000_000, 768).astype('float32')

# 构建 IVF + PQ 索引
quantizer = faiss.IndexFlatL2(768)              # 粗量化器
index = faiss.IndexIVFPQ(quantizer, 768, 1024, 64, 8)  # IVF聚类 + PQ压缩
index.train(doc_vectors[:100_000])               # 用子集训练
index.add(doc_vectors)                           # 添加全部向量

# 检索：输入查询向量，找 Top-10
query = np.random.randn(1, 768).astype('float32')
distances, indices = index.search(query, k=10)
```

### 4.4 RAG 检索增强生成的完整链路

向量检索最经典的应用是 **RAG（Retrieval-Augmented Generation）**——让大模型"查资料"后再回答：

![RAG 检索增强生成流程图](/images/blog/rag-flow.png)

**关键设计决策：**

1. **Chunk 大小**：太小丢失上下文，太大检索不精确。典型值 256-1024 tokens。
2. **Chunk 重叠**：相邻 chunk 之间保留 10%-20% 的重叠，防止关键信息被切断。
3. **重排序（Re-ranking）**：初次检索取 Top-K（如 50 条），用更精确的交叉编码器模型重排序，最终保留 Top-N（如 5 条）。
4. **混合检索**：结合向量检索（语义匹配）和关键词检索（精确匹配），取长补短。

## 五、总结

这篇文章从三个角度梳理了 Embedding 与语义检索：

1. **映射原理**：Embedding 将离散的高维独热编码压缩为低维稠密向量，通过分布式表示捕捉语义。从 Word2Vec 到 text-embedding-3，这个过程越来越精准。

2. **系统角色**：Embedding 是文本世界和数学世界的桥梁，在不同粒度（词、句、文档）上提供语义坐标，支撑搜索、推荐、聚类等任务。

3. **检索流程**：向量相似度检索是整个 RAG 流水线的核心环节，通过 Embedding 向量化 → ANN 索引 → 相似度排序 → 重排序，实现毫秒级的语义搜索。

理解 Embedding，就是理解现代 NLP 系统如何"读懂"文本的第一步。在下一篇中，我们将进一步探讨大模型如何在 Embedding 的基础上，通过工具调用（Function Calling）与外部世界交互，以及 Scaling Laws 如何揭示了规模与智能之间的深层关系。
