# 图型判据与反例

## 何时「值得」配图

用以下信号判断一个位置是否需要图。命中越多越值得：

- **认知负荷高**：纯文字需要读者在脑中反复重构才能理解。
- **空间/时序关系**：数据流、调用链、分层、状态迁移——文字线性表达天然吃亏。
- **对比关系**：A 与 B 的差异（复杂度、性能、结构），一图胜过一段话。
- **抽象缺锚点**：向量、注意力、梯度等抽象概念，需要一个具体意象来"挂钩"。
- **反复被吐槽的点**：读者经常误解、需要解释两遍的概念。

## 何时**不该**配图（反例）

- 文章已经很短、逻辑线性、无空间/数值关系——加图只是装饰。
- 图只是把一段文字原样搬进方框（"换皮文字"），没有增加信息。
- 为凑数而配图（"每篇都该有图"是错误前提）。
- 装饰性花边、与内容无关的氛围图。

**合格结论可以是「这篇文章不需要图」。**

## 五类图型

### 1. 精确图表（matplotlib）
- **适用**：公式曲线、训练/收敛曲线、性能与复杂度对比、精确数值关系、热力图。
- **工具**：`scripts/generate_blog_charts.py`（本仓库既有脚本，沿用它）。
- **要求**：坐标、单位、图例精确；数据来源可追溯到原文。
- **禁止**：用文生图代替（会画错公式与数值）。

### 2. 结构示意图（视觉风格化）
- **适用**：系统架构、模块分层、请求生命周期、数据流、部署拓扑。
- **工具**：`visual-style-guide`（手绘蓝图工程风，博客既有风格，已有 12 个 `scripts/blueprint-*.html` 参考）或 `mermaid-diagram`（标准流程图/时序图，快速可编辑）。
- **选择**：需要"博客风格统一 + 有质感"→ 蓝图风；需要"快速表达流程/时序 + 可编辑"→ mermaid。

### 3. 科普插画 / 类比图（文生图，先出提示词）
- **适用**：抽象概念的具象类比、心智模型、概念隐喻。
- **工具**：`handraw-style`（327 种手绘风格 + 36 主题色）→ 产出双语提示词。
- **注意**：本机**默认不产图**，只出提示词（除非配置了生图通道）。

### 4. 概念对比图
- **适用**：两个以上方案/结构的并列差异。
- **工具**：以精确关系为主 → matplotlib 或 SVG；以示意为主 → 蓝图风 / mermaid。
- **要求**：对比维度必须与原文一致，不得发明维度。

### 5. 文章封面
- **适用**：仅当用户明确要封面时。
- **工具**：`handraw-style` 的 `article-cover-designer`。
- **注意**：封面是"氛围 + 隐喻"，允许弱化精确性；但仍不得与文章主题相悖。

## 一篇文章的配图数量

不设固定配额。典型技术文章 2~5 张是常见区间，但**由内容决定**，不是由数量指标决定。宁可少而准，不要多而水。
