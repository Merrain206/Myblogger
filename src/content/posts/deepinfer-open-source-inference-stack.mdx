## 引子：一次不太像慈善的开源

2026 年 10 月 20 日，DeepSeek 开源了生产环境使用的推理框架 **DeepInfer**，Apache 2.0 协议，连收入数据都放出来了一部分：

- 单集群每天处理约 **155 万亿 Token**；
- 每张 GPU 每小时产生约 **38 美元收入**；
- 一台 8 卡服务器，一个月约 **146 万元人民币**。

网上的第一反应是「把印钞机图纸公开了」。

但如果你把官方 README 从头读到尾，会发现一个很有意思的细节：**在线服务最关键的几块——KV Cache 系统、PD 分离编排、跨机器负载均衡——全都没有开源。**

这就让整件事的性质变了。

它不是一次「把家底全掏出来」的理想主义开源，而是一次非常精准的竞争动作：**把通用的、能建立生态的部分开放，把与自身规模绑定的部分留住。**

理解这一点，比记住那几个收入数字重要得多。

接下来按一条线说清楚：钱从哪来、护城河在哪、哪些招数值得学、这次开源真正改变了什么。

## 一、钱从哪来：不是算法神奇，是重复劳动被消灭了

先建立一个基本认知：**模型和推理引擎是两回事。**

模型是那位「会做菜的厨师」，权重公开了，相当于把厨师请到你家。但后厨还得有人管：客人怎么排队、十口锅怎么同时开火、上一桌的半成品下一桌能不能接着用。

推理引擎就是这套后厨管理系统。它不改变厨师的手艺，但决定了一天能接待多少桌、浪费多少食材。

而大模型回答一个问题，其实分两个阶段：

- **Prefill（读题）**：把整段提问一次性读完，吃的是 GPU 算力；
- **Decode（答题）**：一个字一个字往外写，吃的是显存带宽。

这两件事混在一起会互相拖累——一个很长的提问可能要读几百毫秒，这期间所有正在答题的用户都得排队。所以生产系统会把它们分开部署，也就是新闻里的 **PD 分离**。

到这里都还只是「常识」。真正让成本断崖式下降的，是下面这个数字：

**公开报道称，DeepSeek 生产集群的平均输入缓存命中率约 96%。**

翻译成人话：每 100 个字里，有 96 个字之前已经算过，直接拿来用。

$$
\frac{1}{1 - 0.96} = 25
$$

**读题的工作量，被压到了原来的 1/25。**

这不是某个算法快了 25 倍，而是「大部分活根本不用干」。这也是所有推理优化里最朴素、最有效的一条原则：**先消灭重复劳动，再谈优化算法。**

代价是，缓存要求前缀**一个字都不能差**。少一个空格、换一个换行，缓存就全部失效。所以 DeepSeek 还额外开源了一个小组件 **deepseek-recipe**，专门负责按官方方式拼接提示词——自己拼很容易差一点点，而差一点点，钱就白省了。

## 二、护城河在哪：开源边界就是竞争边界

现在可以回答那个关键问题了：**为什么不把缓存系统也开源？**

看看开源清单就明白了：

| 层次 | 内容 | 是否开源 |
|---|---|---|
| 模型 | V4.1-Flash 权重 | ✅ |
| 算子 | FlashMLA、DeepGEMM、DeepEP 等 | ✅ 此前已开源 |
| 引擎 | 调度、并行、推测解码、采样 | ✅ 本次开源 |
| 协议 | deepseek-recipe | ✅ 本次开源 |
| 缓存 | KV Cache 系统、跨请求复用、淘汰策略 | ❌ |
| 服务 | PD 分离编排、跨机器负载均衡 | ❌ |

缓存系统不是一个算法，而是一整套工程：约 **100 PiB** 的分布式闪存、每秒 10 TiB 的读取带宽、3 天和 7 天两档淘汰策略，全部长在 DeepSeek 自研的 3FS 存储上。

**把它拆出来开源，社区也跑不起来。** 这不是藏私，而是这部分竞争力根本无法脱离原有基础设施独立存在。

这就构成了一个很清晰的判断：

> **开源的边界，就是这家公司的护城河边界。**

它愿意公开「怎么调度、怎么并行、怎么推测解码」，因为这些是行业迟早都会有的能力；它不愿意公开「缓存怎么存、请求怎么分发」，因为这些直接决定了单位成本，而且高度依赖规模。

同样的逻辑也解释了 38 美元这个数字该怎么读：

- 它是**收入**，不是利润。GPU 折旧、电费、网络、存储、闲置率都没扣；
- 它基于低谷时段的定价口径；
- 155 万亿 Token/天、96% 命中率这些数字，**在 GitHub 仓库里验证不了**，属于官方披露和媒体转述。

可以引用，但别当成「跑一遍就能复现」的结论。

## 三、哪些招数值得学，哪些学不了

DeepInfer 里还有几项能力。把它们放在一起看，会发现一个很现实的划分：**有些是规模红利，有些才是工程思想。**

### 学不了的：MoE 专家均衡

DeepSeek 的模型是 MoE 架构，可以想成一家大医院：几百个专科医生，每个病人只看其中几位。模型很大，但每次只动用一小部分。

问题是热门科室会挤爆。写代码、数学这两科几乎每个请求都要找，结果热门诊室排长队，冷门诊室打瞌睡，整个医院的效率被最慢的队拖住。

DeepInfer 的 **EPLB** 会动态把忙碌专家复制到空闲机器上。听起来简单，但 64 到 128 张卡必须放在高速互联的超节点里，普通网络扛不住。

**这一招的入场券是硬件规模，不是代码。** 对绝大多数团队来说，看懂即可，别想着复刻。

### 值得借鉴，但要算账的：推测解码

答题阶段慢，是因为每写一个字都要把整个模型过一遍。**DSpark** 的思路是让一个便宜的小模型先猜 5 个字，大模型一次性检查——猜对了就白赚，猜错了就重来。

它还根据置信度决定「这次要不要猜」：代码补全、结构化抽取这类任务下一个字好猜，值得投机；写小说、开放问答则不适合。

公开报道给出的提升是 **4% 到 7%**。

这个数字很诚实，甚至有点扫兴——论文里经常吹两三倍。但它说明了一个更重要的道理：**生产环境的优化没有银弹，稳定的个位数提升乘以巨大规模，才是真实的钱。**

### 最被低估的：可复现性

同一句话问 AI 两遍，答案不一样，大多数人觉得正常。但有些「不一样」不是随机性，而是浮点误差：GPU 的加法顺序会受这一批请求的组成影响，微小差异经过采样放大，最后变成完全不同的字。

对聊天无所谓，但对回归测试、A/B 实验、事故复现是灾难——你分不清变化来自模型、流量，还是纯粹的数值噪声。

DeepInfer 的 **batch-invariant** 模式让同一段输入不管和谁拼成一批，都得到同样的结果。代价是性能下降，所以它是按需开关。

**这一招反而最值得抄。** 它不需要特殊硬件，只需要在系统设计时把「可复现」当成需求，而不是出事后的调试手段。

## 四、这次开源真正改变了什么

如果只把它当成一条技术新闻，会错过更重要的一层。

### 1. 开源竞争从「模型层」下沉到「系统层」

过去两年，大模型开源的主战场是权重：谁家模型更强、许可更宽松。现在，战场开始转向系统：算子库、推理框架、训练框架、Agent 运行时。

DeepSeek 的路径非常清晰——先开源 FlashMLA、DeepGEMM、DeepEP 这些零件，再开源 DeepInfer 这台整机。

这个变化的含义是：**模型权重会过时，系统能力会沉淀。** 一个团队今年基于 V4.1 做应用，明年可能换模型；但从推理引擎里学到的调度、缓存、可复现性工程，可以一直用。

### 2. 推理引擎正在商品化，但算力没有

DeepInfer 开源后，一个直接后果是：**「自研推理引擎」这件事的稀缺性下降了。**

以前，把开源模型跑到生产可用，是一道很深的护城河；现在，官方把调优过的引擎摆在你面前，差距被压缩到了「你有没有那套缓存基础设施」和「你有没有那么多卡」。

换句话说，**竞争会从「谁的引擎写得好」转向「谁的规模大、谁的缓存命中率高、谁的成本结构更优」。**

这对行业是好事：推理服务会越来越像水电，价格继续往下走。但别误会——**引擎开源不等于算力免费**。省下的软件成本，最终还是要用硬件和规模去换。

### 3. 双硬件栈是一个长期信号

DeepInfer 同时支持英伟达 SM100 和华为昇腾 950。

这不是顺手做的兼容。两套硬件的通信原语、算子接口、内存模型完全不同，要同时支持，意味着抽象层要重做一遍。

它的意义不在于「今天就能在昇腾上跑」，而在于：**国产模型公司开始把「算力来源不确定」当成一个需要长期对冲的工程前提，而不是临时适配。**

顺便纠正一个流传很广的错误：**SM100 不是 H200。** H200 属于上一代 Hopper 架构，不在支持列表；消费级显卡更不行。所谓「开源」，不等于「你家电脑能跑」。

### 4. 它和 vLLM 不是替代关系

很多人第一反应是「DeepInfer 会不会取代 vLLM」。

官方 README 写得很清楚：DeepInfer 最初**主要基于 vLLM 构建**，同时借鉴了 SGLang 和 TensorRT-LLM。

所以它更像是「DeepSeek 官方调优的 vLLM 分支」，只服务一个模型、两类硬件。它的价值是给出一个**官方参考答案**，而不是成为通用基础设施。

真正可能被广泛采用的，反而是那个不起眼的协议层组件 deepseek-recipe——它不绑定硬件，可以接在 vLLM、SGLang 或自研后端前面。

## 五、普通人能拿走什么

说了这么多行业判断，落到具体行动，其实只有几件事。

### 今天就能做的三个习惯

**第一，调整 Prompt 的结构。**

把**稳定不变的内容放最前面**：系统提示、工具说明、知识库片段；把每次变化的内容放后面。这样更容易命中缓存。不需要任何特殊硬件，立刻能省钱。

**第二，给任务分流。**

「长输入、短输出」的任务（摘要、分类、审核）和「短输入、长输出」的任务（写作、代码生成），瓶颈完全不同。哪怕只有一台机器，也值得给它们不同的并发上限和队列，别让长请求堵住短请求。

**第三，把可复现当需求。**

固定随机种子、固定 Prompt 模板、记录完整请求参数。很多团队出事之后才发现，自己连一次历史请求都复现不了。

### 选型上的三个判断

- **模型不是 V4.1-Flash**：直接用 vLLM，DeepInfer 不支持；
- **已有 vLLM 生产栈**：别急着迁引擎，先试 deepseek-recipe 做协议对齐，这是最低成本的收益；
- **有 SM100 或昇腾 950 集群**：把 DeepInfer 当基线跑一遍，用它校准自己的配置，而不是直接上线。

### 评估推理服务时，多问三个问题

如果你在选云厂商或推理服务商，除了价格，可以多问：

1. **前缀缓存的命中率是多少？** 这直接决定单位成本；
2. **P99 延迟是多少？** 平均值好看不代表体验好；
3. **输出是否可复现？** 不能复现的服务，出问题很难追责。

这三个问题，比「跑分多少」更能反映真实成本。

## 结语：开源的是方法，不是规模

回到标题。

DeepSeek 这次开源的，不是一台印钞机，而是一本「怎么把后厨管得更高效」的说明书。

真正值钱的部分——每天 155 万亿 Token 背后的缓存、存储和调度基础设施——没有开源，也很难开源。

但这不代表这次开源没有价值。它至少提供了三条可以带走的判断：

1. **先消灭重复劳动，再谈优化算法。** 96% 的缓存命中率，比任何花哨的算子优化都值钱；
2. **按负载拆系统。** 读题的和答题的抢同一口锅，效率一定上不去；
3. **可复现性是生产系统的底线，不是调试工具。**

至于那台月入 146 万的 8 卡服务器，它属于 DeepSeek 的规模、流量和基础设施。

**我们可以学的，是它为什么能做到；不必幻想复制它的账面数字。**
