## 为什么要做这个

前段时间 12306 全面推行电子发票，纸质报销凭证逐步退出历史舞台。但"车票"这个东西，早已不只是报销凭据——它也是一段旅程的纪念。于是想做一个能生成仿真车票的小工具，既可以自己留作纪念，也能当个趣味生成器分享出去。

这就是车票工具的起点。访问地址：[/tools/ticket](/tools/ticket)

## 第一步：把表格画出来

做车票，首先得搞清楚票面上有哪些信息。翻开一张真实的蓝色报销凭证，从上到下梳理：

- **顶部**：票号、检票口
- **中部**：出发站 → 到达站（含拼音）、车次、日期时间、车厢、座位号、席别
- **底部**：票价、身份证号（脱敏）、乘客姓名、售票站信息

这些信息组合起来，正好是一张表单。用 React 的受控组件建一个 `TicketInfo` 对象，每改一个字段就更新状态，右侧同步预览。表单字段总共 26 个，按逻辑分成出发/到达、车次/时间、座位/价格、乘客/售票四组。

但光是手动填字段不够友好。很多人手里有 12306 的电子发票文本，里面什么信息都有，一条条抄太痛苦了。所以同时接了一个 AI 解析的入口——粘贴原始文本，调 DeepSeek 提取 20 个结构化字段，自动回填表单。

## 第二步：两种颜色，两套风格

真实车票有两种：蓝色的报销凭证，和红色的纪念票。两者不只是颜色不同，排版也不一样。

蓝票信息密度高，顶部有"报销凭证"标题栏，底部有二维码和售票信息；红票更简洁，标题是"纪念票"，没有顶部副标题栏，底部是一行"买票请到 12306 发货请到 95306"。

我选择用两张预先处理好的背景图（`bluebg.png` / `redbg.png`）作为底层，再把文字叠加上去。确保背景图里已有的文字区域和前端渲染的文字互不冲突。

CSS 上的难点在字体和间距。站名用黑体（SimHei），正文用宋体（SimSun），车次号用 Mongolian Baiti——这个字体天然接近票面上那种铁路专用数字。两个字的站名做两端对齐，三个字以上的站名加字母间距。票价数字前面带 `￥`，后面跟"元"。这些东西细节虽小，但缺了哪样都不像。

还有一个难点是票面的斜纹底纹。真实车票在光照下能看到细细的斜纹，我试了好几种方案，最后用 CSS `repeating-linear-gradient` 模拟——两条交叉的 1px 半透明斜线叠加，效果意外地接近原件。

## 第三步：背面也得有内容

车票是有背面的。蓝票背面是"报销凭证使用须知"——6 条细则，蓝底蓝字；红票背面是"乘车须知"——一整段说明文字，白底黑字。

但加背面之后问题来了：预览时正面和背面同时显示，很占空间。解决方案是在预览区域同时渲染正面和背面，背面默认在一个 `display: none` 的容器里——打印时才通过 `@media print` 让背面显示、自动分页。

后来又加了一个背面旋转 180 度的开关。原因是打印出来后物理折叠，背面如果不旋转，字是倒的；旋转 180 度之后，折叠时背面文字就和正面同方向了。每张票独立控制旋转状态，因为批量打印时各张票的需求可能不一样。

## 第四步：从 PDF 下载到原生打印

这是整个项目中最大的架构转向。最初我用的是 `html2canvas` + `jsPDF` 方案——把票面 DOM 截成图片，再塞进 PDF 下载。但实际效果很不理想：

- 中文字体渲染依赖系统字体，不同环境效果不一致
- CSS 渐变和阴影在 Canvas 转 PDF 时效果打折
- 物理尺寸换算总有偏差，打印出来不是太大就是太小

折腾了半天 PDF 排版修复，效果还是差强人意。最终做了一个果断的决定：**放弃 PDF 导出，直接用浏览器原生打印**。

`window.print()` 配合 CSS `@page` 媒体查询，指定 A4 纸张，加上 `-webkit-print-color-adjust: exact` 确保背景色和背景图完整打印。浏览器本身的渲染引擎处理这些比 JS 库靠谱得多——字体、渐变、背景图、布局，全都不用担心。

唯一的小代价是用户需要自己在打印对话框里设置纸张大小和边距，但打印质量和可靠性远比之前强。

## 第五步：批量打印的四角布局

既然原生打印解决了质量问题，下一步就是效率问题——一张一张打太慢了，能不能一次打多张？

真发票的规格是 85.6mm × 53.98mm（信用卡大小）。A4 纸是 210mm × 297mm，理论上可以纵向排 4 张。CSS `@page` 支持 `size: A4 portrait`，配合 `position: fixed` 把 4 张票分别定在四角：

```
左上 (top: 8mm, left: 14mm)    右上 (top: 8mm, right: 14mm)
左下 (top: 135.96mm, left: 14mm)  右下 (top: 135.96mm, right: 14mm)
```

票面原本是 856×540 像素渲染的，需要缩放到物理尺寸。换算关系是 `scale = 85.6mm / 856px ≈ 0.378`，但实际操作中用 CSS `scale()` 配合 `transform-origin: top left` 更稳定。

批量打印列表最多 4 张，超过 4 张自动分页。每张票可以独立切换背面是否旋转——这就是为什么背面旋转状态是每张票独立的。

## 第六步：特殊情况处理

做出来之后，陆续遇到了一些边界情况——每种都需要特殊处理：

**无座**。座位号显示"无座"，末尾不需要加"号"字。

**不对号入座**。这是一种特殊的席别，没有车厢号和座位号。表单中直接隐藏这两个字段，席别名称占据它们的位置。

**卧铺**。座位号的标签从"座位号"变成"铺位号"，额外多出一个"铺位类型"下拉（上/中/下铺）。Preview 里也要展示这个类型。

**硬卧代硬座**。最复杂的特殊席别。它的座位号格式是"数字+字母"（如 12A），字母表示铺位在过道的位置。表单上用独立的数字输入框和字母下拉框分别收集，前端展示时再组合起来。

**新空调硬座、硬卧代硬座等复合席别**。席别名称偏长，在票面上的位置需要做偏移调整，否则会跟相邻文字重叠。

这些特殊处理加起来其实代码不多，但每一步都是对着真实票面照片反复比对后才确定的。

## 总结

整个车票工具从第一版到当前版本，经历了 6 次提交，集中在 5 月 23 日到 6 月 4 日的两周内：

1. 搭骨架：表单 + 预览 + AI 解析
2. 调细节：红蓝票面样式
3. 补背面：正反面同时预览
4. **架构转向**：从 PDF 导出切换到原生打印
5. 提效率：批量打印四角布局
6. 加灵活度：背面旋转独立控制

最有价值的教训是那条架构决策——当第三方方案（html2canvas + jsPDF）在核心指标（打印质量）上始终差一口气时，果断退回浏览器原生能力反而是更优解。不是什么时候都得用库，有时候最可靠的方案就藏在 `window.print()` 里。

工具页面已部署在 [merrain.cn/tools/ticket](https://merrain.cn/tools/ticket)，欢迎试用。
