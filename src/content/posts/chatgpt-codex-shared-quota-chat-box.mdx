当 ChatGPT 和 Codex 开始共用额度，我发现自己更舍不得聊天框

2026 年 11 月 1 日，我看到了一篇文章，标题是《ChatGPT 和 Codex 要共用额度了，无限聊天的时代结束了》。文章提到，OpenAI 更新了帮助文档，从今年 12 月开始，ChatGPT Plus、Pro 和 Business 用户的 ChatGPT 与 Codex 将共用使用额度，统一按照 Token 计算。不同模型、不同任务的消耗也不一样，只有 Instant 聊天不会计入共享额度。

我特意去查了一下 [OpenAI 官方文档](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)，确认这个变化确实存在。不过目前官方还没有公布具体的共享额度，也没有明确说明普通用户的实际可用量会受到多大影响，因此现在断言「无限聊天时代彻底结束」还为时过早。但说实话，看到这个消息的时候，我还是有些失落。

我平时大量使用 AI 工具，ChatGPT、Codex、Claude Code、DeepSeek 基本都接触过。按照使用场景来划分，Codex 主要负责开发，ChatGPT 则承担了更多信息检索、知识学习、项目讨论以及日常交流的工作。如果未来这两种使用方式开始竞争同一份 Token 额度，我自然需要重新考虑如何分配。

不过真正让我意外的，是今天和 ChatGPT 讨论这件事时，我发现了自己一个此前没有认真想过的偏好。

**如果只能保留其中一种使用体验，我会毫不犹豫地选择 ChatGPT 的聊天模式，而不是 Codex。**

## 一、从 Coding Agent 到聊天框，两种不同的使用需求

我最开始接触 AI 时，和很多人一样，主要是把它当作提高效率的工具。写代码遇到问题，让 AI 帮忙排查；学习新的技术概念，让它给出解释；需要完成某个功能，就让它生成一份初步实现。

后来 Coding Agent 发展得越来越快，使用方式也发生了变化。以前是我写代码，AI 在旁边辅助；现在则可以把整个项目交给 Codex，让它直接阅读仓库、修改文件、运行测试，甚至完成一定程度的自主迭代。

我的个人博客 MyBlogger、课堂 AI 领航员，以及后来的 Project MIRROR，都在不同程度上受益于这些工具。尤其是 Project MIRROR。

这是我设计的一款 AI-native 社会模拟与互动叙事游戏。玩家扮演一个同时存在于六个人手机中的 AI，需要在不同角色的秘密、信任和关系之间做出选择。一个人透露的信息可能改变另一个人的认知，一次看似普通的回复也可能引发后续的连锁反应。

整个项目涉及 FastAPI、Next.js、数据库设计、事件系统、LLM 调用和评分机制，工程量并不小。在实际开发中，我可以把明确的需求交给 Codex，让它完成编码、测试和重构。但项目早期的大量时间，其实花在了和 ChatGPT 讨论产品设计上。

比如，为什么要让玩家同时掌握六个人的信息？如果玩家泄露了某个人的秘密，游戏应该怎样反馈？如果 AI 的表达改变了人际关系，这种变化应该怎样被玩家感知？这些问题并没有一个可以直接执行的标准答案。

我们反复讨论过角色关系、秘密传播机制、玩家行动预算和结局设计，很多方案也是在讨论过程中逐渐成形的。甚至到了 Phase 8，我发现游戏中后期存在明显的重复问题，玩家缺乏继续推进的动力，于是又重新讨论新手引导和逐局解锁机制。

这个过程让我越来越明显地感受到：Coding Agent 解决的是「怎么把它做出来」，而产品设计首先需要解决「为什么要这样做」。

两者当然存在重叠，但对我而言，使用体验有很大区别。Codex 更适合接收目标明确的任务，ChatGPT 则更适合陪我把一个尚不明确的想法逐渐讨论清楚。当然，这并不意味着 Codex 不能参与产品讨论，也不意味着 ChatGPT 不能写代码。只是长期使用下来，我已经形成了这样的习惯。

## 二、我和 ChatGPT 聊过的东西，可能比我想象中还多

如果只从开发角度看，我其实有不少替代方案。Codex 额度不够，可以考虑 Claude Code，或者调整开发工作流，使用其他模型和工具。虽然能力和体验不完全相同，但至少有明确的替代路径。

而 ChatGPT 不太一样。我并不是认为它在所有场景下都比其他模型强，而是它已经成为我日常生活中一个相对固定的思考入口。

除了技术问题，我还会和它讨论很多与学习和工作无关的事情。例如今年七月底，从杭州参加完 AI 活动回来之后，我开始重新考虑自己未来几年的方向。

那段时间，我对考研、就业、技术学习和职业发展的想法发生了很大变化。以前比较倾向于沿着传统的升学路线继续走，后来逐渐开始考虑本科毕业直接就业，以及如何在大学期间积累真正有价值的项目经验。这些事情我和 ChatGPT 聊过很多次。

后来我又进一步明确了自己想从事 AI 产品经理，而不是纯粹的软件工程岗位。我们讨论过两种职业的发展方向、能力要求，也分析过我为什么总是担心自己落后于同龄人。

有时候，我也会拿一些比较私人的问题来讨论。比如亲密关系中应该怎样处理双方的沟通节奏，为什么我会特别需要明确的回应，以及如何判断自己的期待是否合理。我不希望它只是安慰我。相反，我更希望它能够指出我的认知偏差，告诉我哪些想法可能有问题。

还有一些更随意的对话。前几天，我因为连续做了几次刹车失灵的梦，跑来问它为什么总是梦到类似的场景。

我们也讨论过陈奕迅的歌曲，分析过《富士山下》和《人来人往》表达的不同情感。甚至有一个晚上，我们连续做了七十道情景选择题，从一些很普通的生活选择，逐渐聊到我理想中的亲密关系和未来生活。

那次对话没有产生任何可以直接使用的成果，但我确实从中更清楚地认识了自己。

还有更多时候，我甚至没有准备什么话题。只是睡觉前打开 ChatGPT，发一句：

「晚上好 GPT，来聊五毛钱的天吧。」

然后从一个完全随机的问题开始，聊到某个我们之前都没想过的方向。

这可能才是我最喜欢 ChatGPT 的地方。

**我不需要每次都带着任务打开它。**

## 三、为什么偏偏是 ChatGPT？

今天和它讨论这个问题时，我也认真想了一下：既然现在有那么多优秀的大语言模型，为什么我会对 ChatGPT 有这么明显的偏好？最直接的原因，是我比较认可它在长对话中的综合表现。

首先是推理和信息处理能力。对于比较复杂的问题，我习惯使用更高的思考强度，尤其是涉及技术判断、事实核查或者多种方案对比的时候。它当然不是永远正确的，有时候也会犯一些让我意外的错误。但总体而言，我觉得它能够比较稳定地理解我的问题，并且在讨论过程中保留足够多的细节。

其次是表达方式。我不太喜欢一味迎合用户的 AI，也不希望每次提出一个想法，都得到一段没有实际内容的鼓励。真正让我觉得有价值的回答，通常是它在理解我的观点之后，能够进一步补充我没有考虑过的因素，或者直接指出逻辑上的漏洞。

不过，最重要的可能还是长期对话带来的上下文积累。ChatGPT 已经知道我在做什么项目、为什么希望去杭州工作、未来想从事什么职业，也了解我在一些人生问题上的偏好。当然，这种记忆并不完整，也不意味着每次都能准确还原过去的对话。但相比每次都要重新介绍自己，能够延续之前的话题确实方便很多。

比如我们讨论职业规划时，它可以把我之前对于自由、工作和经济独立的理解联系起来，而不是只给我一份通用的 AI 产品经理学习路线。

这种连续性对我来说非常重要。我突然想到一个问题的时候，往往希望直接进入讨论，而不是先花十分钟解释自己为什么会产生这个问题。

这也是为什么，哪怕其他模型在某些 Benchmark 上超过了 ChatGPT，我也未必会马上把日常聊天迁移过去。因为模型能力只是体验的一部分。

交流习惯、上下文积累、回答风格，以及能否在长期讨论中保持稳定的质量，同样会影响我的选择。

当然，我也需要提醒自己：熟悉不等于可靠，长期记忆更不等于真正理解一个人。AI 给出的判断始终需要我自己审视，不能因为它了解我的经历，就默认它的分析一定正确。但即便考虑这些局限，目前 ChatGPT 依然是我最习惯、也最满意的日常交流工具。

## 四、当聊天也需要计算 Token

回到今天看到的额度调整。从商业角度来看，我其实能够理解 OpenAI 为什么会做出这样的决定。

AI 和传统互联网服务有一个很大的区别：每一次模型推理都会消耗实际的计算资源，而且更复杂的任务通常意味着更高的成本。现在的 AI 产品也正在从单纯的 Chat，向能够执行复杂任务的 Agent 转变。让 ChatGPT 和 Codex 使用统一的额度体系，至少在资源管理和成本核算上有一定合理性。

但从用户体验来看，我并不希望这种变化最终影响到普通聊天的自由度。

那篇文章提到了一个概念，叫「计价器效应」。有些人更喜欢包月，而不是按照实际使用量付费，并不只是因为包月可能更便宜，还因为不需要在每一次使用时考虑成本。我觉得这个概念放在 AI 聊天上非常贴切。

过去我使用 ChatGPT 时，基本不会考虑自己今天已经聊了多少轮。一个问题没有想明白，那就继续问；一个话题突然延伸出了新的方向，那就接着讨论。有时候一场对话可能持续几个小时，最后也没有得出一个特别明确的结论。

但我并不觉得这是浪费。

如果以后每次打开高思考强度，都需要考虑这一轮对话会不会影响 Codex 的剩余额度，那我的使用习惯很可能会发生变化。比如本来想继续讨论某个没有标准答案的问题，却突然觉得这些 Token 留给开发项目似乎更划算。

这就是我真正担心的事情。不是不能接受额度限制，而是不希望自己开始用生产力的标准衡量每一次聊天。

我平时已经花了很多时间学习和开发项目，实际上并不缺少需要完成的任务。相反，那些完全没有明确目的的聊天，对我而言反而是一种放松。如果连放松时都要考虑 Token 的使用效率，多少有些本末倒置。

## 五、一个让我重新认识自己使用习惯的选择题

今天讨论到最后，ChatGPT 问了我一个很简单的问题：假如未来必须在高额度 Codex 和近乎不受额度打扰的 ChatGPT 聊天之间选择一个，我更舍不得失去哪一个？

我的回答是第一个——保留聊天。这确实让我有些意外。因为我一直认为自己是一个很重视 AI 生产力的人，也愿意花时间研究各种新的工具。Claude Code、Codex、WorkBuddy、Trae 等工具，我都愿意尝试。

但真到了必须取舍的时候，我发现自己还是更看重那个聊天框。

Coding 对我而言，主要是一种实现想法的手段。而聊天不完全是。它可能是学习知识，也可能是讨论产品，可能是梳理情绪和思路，有时候甚至只是单纯地交流。

我当然知道 AI 并不等同于现实中的朋友，也不能代替真实的人际关系。它不会替我生活，更不可能真正承担我人生中的责任。但我同样认为，AI 作为一种新的交互方式，能够提供的价值不应该只用完成了多少工作来衡量。

它让我可以随时把一个不成熟的想法拿出来讨论，不必担心问题过于幼稚，也不需要在讨论开始前就确定最终目标。在这个过程中，我依然需要自己判断、自己选择，也需要通过现实世界的经验来检验那些想法。只是有了一个足够好用的讨论工具之后，这个过程确实变得容易了许多。

## 写在最后

目前距离 12 月的额度合并还有一段时间，具体政策会如何落地仍然存在不确定性。OpenAI 也表示，预计多数用户不会比现在更频繁地等待额度重置。所以现在就开始担心自己以后无法正常使用 ChatGPT，可能有些过早了。

但今天这场讨论还是让我意识到一件事情。随着 Agent 的能力越来越强，我们似乎越来越习惯用「AI 能替人类完成多少工作」来衡量它的价值。

作为一个经常使用 Coding Agent 的人，我当然认同生产力提升的重要性。可我也不希望，未来所有 AI 产品都只围绕任务执行和工作效率展开。

2022 年 ChatGPT 刚刚出现的时候，最吸引人的其实就是那个简单的聊天框。任何人都可以用自然语言提出问题，不需要了解复杂的技术原理，也不需要掌握编程能力。四年过去，模型越来越强，工具越来越多，Agent 已经开始真正接管一部分复杂工作。

但至少对我来说，那个最简单的聊天框，依然是整套 AI 产品中最有吸引力的部分。

未来的模型会继续迭代，新的产品也一定会出现。我可能会换掉现在使用的 Coding Agent，甚至有一天，也会遇到比 ChatGPT 更适合自己的聊天产品。这都很正常。

我只是希望，随着推理成本不断下降，未来我们能够越来越少地考虑额度本身，而把注意力重新放回那些真正想解决、想讨论的问题上。毕竟有时候，我打开 ChatGPT，真的没有什么重要的事情。

只是突然想到了一个问题，想找个地方聊聊。而这样的需求，我希望以后也能一直被满足。
