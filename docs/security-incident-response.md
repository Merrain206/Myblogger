# 安全事件响应手册

## 最高优先级

1. 将仓库临时设为私有，暂停相关部署和同步入口。
2. 轮换管理员密码和 `AUTH_TOKEN_SECRET`，重启所有实例，使现有登录 Cookie 全部失效。
3. 检查并视情况轮换 DeepSeek/API Key，不要把旧值写入日志或工单。
4. 按 Cloudflare 手册清除敏感缓存并部署 API、认证 Cookie、RSC 和动态 HTML 的绕过规则。
5. 车票 PDF 中的身份信息按“已经公开泄露”处理，评估通知、下架和合规义务。

## 日志调查

按时间、来源 IP、状态码、请求数量和资源 ID 调查以下事件，但不要复制存档正文、问题内容、姓名、身份证号、车票号、API 响应或 Cookie：

- 未授权的 archives GET/POST/DELETE；
- sync-media 与 Hermes 同步调用；
- 大量或异常高成本 AI 请求；
- 异常 WebSocket Origin、连接风暴、超大或高频消息；
- 可疑排行榜提交或重复 game ID；
- 认证失败突增、同一来源的限流命中。

保全原始日志的访问控制和哈希，另建只含脱敏元数据的调查时间线。确认影响范围后，再决定是否恢复服务。

## 安全联系

站点提供 `/.well-known/security.txt`。收到报告后应确认收件、分级、复现、修复、验证并协调披露时间；不要要求报告者通过不安全渠道发送真实个人数据或有效密钥。
