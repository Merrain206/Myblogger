## 为什么用 Tailwind CSS

先承认一个事实：第一次看到 Tailwind 代码的人，几乎都会觉得它"又丑又长"——一大串 class 堆在 HTML 上，看起来像是把所有 style 属性换了个写法。

但用了几个月之后，你会发现一个微妙的变化：**再也不想回到传统 CSS 了**。原因很实际：

1. **无命名负担** — 不用给每个 `div` 起一个语义化 class 名称，不用在 BEM 和 CSS Modules 之间纠结
2. **一致性内置** — 所有间距、颜色、字号都来自统一的设计 token 系统，不会出现 `padding: 7px` 这种随手写的魔法数字
3. **响应式开箱即用** — `sm:` `md:` `lg:` 前缀无感切换，不需要额外的媒体查询
4. **暗色模式零成本** — `dark:` 前缀搞定，不用再写两套样式
5. **打包体积自动优化** — 生产构建时只会保留你用到的 class，不会像 Bootstrap 那样拖一整坨

如果你跟我一样从"Tailwind 丑死了"到"真香"，这篇文章的每个技巧应该都能在实战中用上。

## 实用技巧

### 1. 自定义设计 token

不要直接用 Tailwind 默认的 blue-500、slate-600 到处写。在 `tailwind.config.ts` 中定义属于你项目的语义化颜色和间距：

```typescript
// tailwind.config.ts
export default {
  theme: {
    extend: {
      colors: {
        brand: {
          DEFAULT: "#0ea5e9",
          light: "#38bdf8",
          dark: "#0369a1",
        },
        surface: {
          DEFAULT: "#ffffff",
          muted: "#f8fafc",
          dark: "#0f172a",
        },
      },
      spacing: {
        section: "clamp(3rem, 5vw, 6rem)",
      },
      fontFamily: {
        display: ["var(--font-display)", "system-ui"],
        body: ["var(--font-body)", "system-ui"],
      },
    },
  },
};
```

这样当你一年后回来看代码时，`bg-brand` 比 `bg-blue-500` 更能表达意图——"这是品牌色"，而不是"这是蓝色"。

### 2. 暗色模式

Tailwind 的 `darkMode: "class"` 策略让你精确控制暗色模式：

```typescript
// tailwind.config.ts
export default { darkMode: "class" };
```

使用时只需在 HTML 根元素切换 `dark` class：

```html
<div class="bg-surface text-slate-900 dark:bg-surface-dark dark:text-slate-100">
  <h2 class="text-brand dark:text-brand-light">标题</h2>
  <p class="text-slate-600 dark:text-slate-400">正文内容...</p>
</div>
```

**一个常见的坑**：只在 `tailwind.config.ts` 中设了 `darkMode: "media"`（默认值），然后发现手动切换不生效。`media` 模式只看系统偏好，用户无法手动切换。要想手动切换，必须用 `class` 模式。

### 3. 任意值与即时定制

Tailwind 的方括号语法让你可以在不修改配置的前提下使用任意 CSS 值：

```html
<!-- 任意颜色 -->
<div class="bg-[#ff6b6b] text-[#2d3436]">自定义配色</div>

<!-- 任意尺寸 -->
<div class="w-[320px] h-[180px]">固定尺寸卡片</div>

<!-- 任意 CSS 属性（3.2+） -->
<div class="[mask-image:linear-gradient(to_bottom,transparent,black)]">
  渐变遮罩
</div>

<!-- 任意选择器 -->
<li class="[&:nth-child(3)]:col-span-2">第三个元素横跨两列</li>
```

这个特性尤其适合**快速原型**——先用方括号写死值把效果调出来，确认后再把重复出现的值提取到配置中。

### 4. 组合模式：群组悬停与兄弟选择器

Tailwind 提供了丰富的组合选择器，避免写自定义 CSS：

```html
<!-- group: 父元素被 hover 时改变子元素 -->
<div class="group cursor-pointer rounded-xl border p-6 transition-all hover:-translate-y-1 hover:shadow-lg">
  <h3 class="text-lg font-bold group-hover:text-brand">卡片标题</h3>
  <p class="text-slate-500 group-hover:text-slate-700">悬停整张卡片时...</p>
  <svg class="h-6 w-6 opacity-50 group-hover:opacity-100">...</svg>
</div>

<!-- peer: 同级元素状态联动 -->
<input class="peer" type="checkbox" id="menu-toggle" />
<label class="peer-checked:hidden" for="menu-toggle">展开菜单</label>
```

`group` 和 `peer` 配合使用能实现很多"无 JS"的交互效果，减少不必要的事件监听。

### 5. 动画与过渡

直接用 utility class 控制动画，不需要手写 keyframes：

```html
<!-- 按钮交互 -->
<button class="rounded-lg bg-brand px-4 py-2 text-white
               transition-all duration-200 ease-out
               hover:bg-brand-dark hover:shadow-lg hover:shadow-brand/25
               active:scale-95 active:shadow-none">
  点击我
</button>

<!-- 骨架屏加载 -->
<div class="animate-pulse rounded-lg bg-slate-200 dark:bg-slate-700 h-4 w-3/4" />
<div class="animate-pulse rounded-lg bg-slate-200 dark:bg-slate-700 h-4 w-1/2 mt-2" />
```

关于动画的一个重要准则：**只动画 `transform` 和 `opacity`**。这两个属性由 GPU 合成，不会触发重排。Tailwind 的内置动画类（`animate-spin`、`animate-pulse` 等）都遵循这个原则。

### 6. 响应式设计策略

Tailwind 的响应式断点是移动优先的——不加前缀的 class 应用于所有屏幕，大屏幕加断点覆盖：

```html
<!-- 移动端单列 → 平板两列 → 桌面三列 -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6">
  <!-- 卡片 -->
</div>

<!-- 移动端堆叠 → 桌面端并排 -->
<section class="flex flex-col lg:flex-row lg:items-center lg:justify-between gap-8">
  <div class="lg:w-1/2">左侧</div>
  <div class="lg:w-1/2">右侧</div>
</section>

<!-- 移动端文字 → 桌面端文字 -->
<h1 class="text-3xl md:text-4xl lg:text-5xl font-bold">响应式标题</h1>
```

开发时建议把浏览器宽度拉到 375px 开始写样式，然后逐渐拉宽加断点覆盖。从大到小写反而容易遗漏移动端问题。

### 7. 容器查询（Container Queries）

Tailwind CSS v3.4+ 内置容器查询支持，根据**父元素**宽度而非视口来调整布局：

```html
<div class="@container">
  <div class="grid grid-cols-1 @md:grid-cols-2 @lg:grid-cols-3 gap-4">
    <!-- 无论视口多大，只要父容器够宽就显示多列 -->
  </div>
</div>
```

这在构建可复用的布局组件时特别有用——组件不关心页面宽度，只关心自己被分配了多少空间。

### 8. 使用 `@layer` 管理自定义样式

当 utility class 不够用时，用 `@layer` 将自己的 CSS 注入到 Tailwind 的级联层级中：

```css
/* globals.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  h1 { @apply text-3xl font-bold; }
  h2 { @apply text-2xl font-semibold; }
}

@layer components {
  .card {
    @apply rounded-xl border border-slate-200 bg-white p-6
           transition-all hover:-translate-y-1 hover:shadow-lg
           dark:border-slate-700 dark:bg-slate-800;
  }
}

@layer utilities {
  .text-balance { text-wrap: balance; }
}
```

`@apply` 要谨慎使用——它适合抽取真正重复出现的模式（如 `.card`），而不是把每一个 `<div>` 的 class 都抽成组件。后者会导致组件名泛滥，回到了传统 CSS 的命名困境。

## 常见组件模式

### 卡片组件

```html
<article class="card">
  <div class="aspect-video overflow-hidden rounded-lg">
    <img class="h-full w-full object-cover transition-transform duration-300 hover:scale-105"
         src="/thumbnail.jpg" alt="文章封面" />
  </div>
  <div class="mt-4 space-y-2">
    <span class="inline-block rounded-full bg-brand/10 px-2 py-0.5 text-xs font-medium text-brand">
      前端
    </span>
    <h3 class="text-lg font-bold">文章标题</h3>
    <p class="text-sm text-slate-500 dark:text-slate-400">
      文章摘要，限制在两行以内...
    </p>
    <time class="text-xs text-slate-400">2026-05-01</time>
  </div>
</article>
```

### 表单输入框

```html
<label class="space-y-1.5">
  <span class="text-sm font-medium text-slate-700 dark:text-slate-300">邮箱</span>
  <input
    type="email"
    class="w-full rounded-lg border border-slate-300 bg-white px-3 py-2 text-sm
           placeholder:text-slate-400
           focus:border-brand focus:outline-none focus:ring-2 focus:ring-brand/20
           disabled:cursor-not-allowed disabled:opacity-50
           dark:border-slate-600 dark:bg-slate-800 dark:text-slate-100"
    placeholder="you@example.com"
  />
</label>
```

`focus:ring` 和 `focus:border` 的组合提供了清晰的焦点指示——这对键盘导航的可访问性至关重要。

### 通知徽章

```html
<button class="relative p-2">
  <svg class="h-6 w-6" />
  <span class="absolute -right-0.5 -top-0.5 flex h-5 min-w-[20px] items-center justify-center
               rounded-full bg-red-500 px-1 text-[10px] font-bold text-white">
    3
  </span>
</button>
```

`min-w-[20px]` 确保单个数字也是圆形，双位数字自动拉宽——不需要 JavaScript 计算。

### 分割线

```html
<div class="flex items-center gap-4">
  <div class="h-px flex-1 bg-slate-200 dark:bg-slate-700" />
  <span class="text-sm text-slate-400">或者</span>
  <div class="h-px flex-1 bg-slate-200 dark:bg-slate-700" />
</div>
```

用 `flex-1` 让分隔线占据剩余空间，文字居中不变。比手写绝对定位简单得多。

## 避坑指南

1. **不要用 `space-y` 和 `gap` 同时给同一个 flex/grid 容器**——两者会叠加生效，间距看起来翻倍
2. **`@apply` 不要滥用**——它在编译时会内联，大量使用会增大 CSS 体积，且破坏 Tailwind 的"源码即样式"优势
3. **生产构建确保 `content` 路径正确**——如果新增了组件目录但没加到 `content` 配置中，那些 class 会被 purge 掉，样式不生效
4. **善用 Tailwind CSS IntelliSense 插件**——VS Code 装上后有 class 自动补全、悬停预览、颜色提示，效率翻倍

## 总结

Tailwind CSS 的价值不在于"少写 CSS"，而在于**一套完整的设计约束系统**——你不再需要做 "这个间距用 5px 还是 6px" 这样的微观决策，转而把精力放在页面结构、交互流程和数据流上。

几个核心原则：

- **设计 token 先行**：先定义好颜色、间距、字号的语义化名称，再写组件
- **移动端优先**：375px 宽度写基础样式，大屏幕加断点覆盖
- **善用组合选择器**：`group`、`peer` 能省掉大量 JS 交互代码
- **构建结果验证**：`npm run build` 后用 Chrome DevTools 的 Coverage 面板检查 CSS 利用率
