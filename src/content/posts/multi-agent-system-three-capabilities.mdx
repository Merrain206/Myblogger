## 一、引言：从"一个 Agent"到"一群 Agent"

在前两篇文章中，我们讨论了单个 Agent 的架构设计（郝建业 + 张航帆）和 Agent 如何在环境中学习进化（温颖）。这些讨论都围绕一个前提：**Agent 以个体为单位运作**。

但真实世界的场景往往更复杂。一个电商平台的搜索推荐系统背后可能有数十个 Agent 在分工协作——有的负责意图识别，有的负责商品召回，有的负责排序，有的负责生成推荐理由。一个大型代码仓库的维护可能同时跑着上百个 Coding Agent——有的修 bug，有的补测试，有的做重构。

当从"一个 Agent"扩展到"一群 Agent"，问题的性质就变了。

周浩老师（清华大学智能产业研究院副研究员）在博见社的报告《大规模智能体系统的三项基础能力》，正是一个从系统级视角审视 Agent 的宏观框架。相比前两篇聚焦在"怎么做"和"怎么学"，周浩老师在回答一个更根本的问题：**当成百上千个 Agent 同时运转，底层需要什么样的能力来支撑？**

他只用了三张图——但每一张都高度凝练，需要展开来才能理解其中的分量。

## 二、能力一：强大的底座模型——十年的 AI 基石

![十年 AI 基石积累——从 Seq2Seq 到 GPT-3](/images/blog/report-multi-agent-1.jpg)

这张图是一份 AI 核心技术演进的时间线，从 2014 年的 Seq2Seq 到 2020 年的 GPT-3，六个里程碑节点一字排开。右侧是一个指向未来的问号——暗示着下一个突破正在酝酿。

图中的引用量数据令人震撼：**Transformer 论文引用 190K，BERT 引用 140K**。这些数字不是作者在炫论文——而是在说明一件事：**大规模智能体系统不是凭空出现的，它建立在过去十年大模型（尤其是 Transformer 架构）的爆发式发展之上。**

每一项里程碑都在递进式地解决一个问题：

- **Seq2Seq（2014）**：让神经网络能处理序列到序列的转换——Agent 能"理解输入、生成输出"从这里开始。
- **Attention（2015）**：让模型知道在长序列中"该看哪里"——这是 Agent 处理长上下文的基础。
- **Transformer（2017）**：彻底抛弃 RNN，全注意力架构——迄今几乎所有大模型的骨架。
- **BERT（2018）**：双向编码器，让模型理解上下文的"前"和"后"——Agent 的语义理解能力从此飞跃。
- **GPT-2 / GPT-3（2019-2020）**：从 1.5B 到 175B，涌现能力开始出现——Agent 开始展现出超越简单模式匹配的推理行为。

周浩老师的意思是：**大规模智能体系统需要的是"参数规模足够大、先验知识足够丰富"的底座模型**——这是支撑一切上层智能行为的基础。如果底座模型的语义理解能力不够，再精巧的 Agent 架构也是空中楼阁。

> 在之前的文章[《大模型如何学会使用工具》](/blog/llm-tool-calling-scaling-laws)中，我们讨论了 Scaling Laws——训练阶段的性能如何随参数量、数据量和算力增长。而这里周浩老师从另一个角度切入：**底座模型的规模不只是"更准"，更是大规模 Agent 系统能够存在的物理前提。** 你没有足够强的基座，多 Agent 之间的通信和协调根本无从谈起。

## 三、能力二：自主进化与持续学习——智能的螺旋

如果图 1 讲的是"土壤"，那图 2 讲的就是"生命力"：

![智能与经验的闭环演化——从 L1 到 Ln 的螺旋上升](/images/blog/report-multi-agent-2.jpg)

这张图的左侧是一个简洁到极致的循环——"智能（Intelligence）"与"经验（Experience）"的生生不息循环：智能体在环境中生成经验，同时通过学习把经验反哺给智能。右侧的折线图则揭示了**智能水平的提升不是一条平滑的直线，而是智能与经验互相交织、螺旋上升的演化过程（从 L1 到 Ln）**。

这个螺旋结构呼应了前两篇文章的核心议题：

- 郝建业老师的 **Hermes** 框架强调"执行后经验沉淀"，把一次性任务转化为可复用的 Skills——这正是"经验反哺智能"的工程实现。
- 温颖老师提出的 **LLE 范式转变**——Agent 不仅要行动，更要"写回自身"——这正是"智能体更新自己的学习接口"的理论表述。
- 张航帆老师的 **Self-Harness**——弱点挖掘 → 方案提议 → 回归验证的循环——正是"智能与经验螺旋上升"的工程化闭环。

周浩老师把这一点提升到了**大规模系统的基础能力**的高度：不是某个 Agent 的"加分项"，而是整个系统能否持续运转的必要条件。如果缺乏这种闭环进化机制，Agent 群体会在几轮交互之后就变得僵化——它们不知道发生了什么、不知道为什么失败、更不知道如何改进。系统将永远停留在部署那一刻的知识水平上。

## 四、能力三：高效推理与系统化响应——并行生成的"加速器"

第三项能力最容易被忽视，但在工程实践中却可能是最大的瓶颈：

![低时延基座模型——并行生成系列工作](/images/blog/report-multi-agent-3.jpg)

这张图展示了清华大学 AIR 团队在**非自回归/并行生成**领域的长期技术积累。从早期的 NAT（Non-Autoregressive Transformer）到 GLAT，再到最新的 diff-GLAT，一条蓝色实线逐渐攀升——这条线代表并行生成模型的性能。虚线是传统自回归模型的参照线。关键节点在 **2024 年**：并行生成模型的性能终于达到了主流基座模型的相当水平。

**为什么这项技术对大规模 Agent 系统如此重要？**

自回归生成（即当前大多数 LLM 的工作方式）是逐 token 串行输出的——必须先算完第一个 token 才能算第二个。当成百上千个 Agent 同时需要推理时，每一个的等待时间叠加起来，系统吞吐量会被串行生成的速度牢牢卡住。

在之前的文章[《大模型如何学会使用工具》](/blog/llm-tool-calling-scaling-laws)中，我们讨论了训练阶段的 Scaling Laws——更多参数、更多数据、更多算力。但周浩老师的报告揭示了一个容易被忽视的维度：**推理阶段的效率同样是 Scaling 的瓶颈。** 你可以堆算力把模型训练得更大，但如果推理阶段每个 Agent 都要排队等前一个 Agent 输出完，系统规模的扩展就有一个不可逾越的天花板。

而非自回归/并行生成技术的突破，正在将这个天花板推高。它让模型能够**同时生成多个 token**，大幅缩短每次推理的延迟，使得多 Agent 场景下的实时响应和低成本并发成为可能。

> **一句话总结**：并行生成是智能体系统的 **"加速器"**——没有它，底座模型再强、进化机制再好，系统也会在高并发场景下瘫痪。

## 五、三项能力的相互关系

把这三项能力放在一起看，它们不是孤立的，而是**互为基础、层层递进**的：

```
┌─────────────────────────────────┐
│  能力三：高效推理（高速神经网络）   │  ← 让系统能"跑得快"
├─────────────────────────────────┤
│  能力二：自主进化（持续学习）       │  ← 让系统能"越跑越好"
├─────────────────────────────────┤
│  能力一：强大底座（大模型基石）      │  ← 让系统"有东西可跑"
└─────────────────────────────────┘
```

- **没有能力一**，Agent 连最基本的语义理解和推理都做不好——多 Agent 之间的通信和协调根本无从谈起。
- **没有能力二**，系统在几轮交互之后就会僵化——Agent 不知道发生了什么、不知道为什么失败、更不知道如何改进。
- **没有能力三**，当成百上千个 Agent 同时需要推理时，串行生成的速度会成为整个系统的瓶颈——并发数再高，每个 Agent 的响应延迟叠加起来也会拖垮整体吞吐量。

如果说郝建业老师告诉我们 **Agent 架构该怎么搭**（文章一），温颖老师告诉我们 **Agent 该怎么学**（文章二），那么周浩老师的报告就是在回答：**当这一切都搭好之后，让成百上千个 Agent 同时运转起来，还需要什么？**

答案是这三样东西——缺一不可。

## 六、总结

周浩老师的三张图如果单独看每一张，会觉得信息量不大。但在听了前面郝建业和张航帆关于 Agent 架构的报告、以及温颖关于 LLE 下 RL 范式的报告之后，这三张图恰好构成了一个**系统级的收束**：

1. **底座模型**提供了大规模 Agent 系统赖以生存的"土壤"——从 Seq2Seq 到 GPT-3，十年积累，Transformer 引用 190K 不是数字而是地基厚度。
2. **智能与经验的螺旋**赋予了系统持续进化的"生命力"——不只是一个 Agent 在成长，而是一整个 Agent 群体在经验中迭代。
3. **低时延并行生成**为系统安装了"高速神经网络"——让成百上千个 Agent 的推理不再是瓶颈，让高并发场景从理论走向现实。

这三项能力环环相扣，共同勾勒出了一个成熟、高效、具备持续进化可能的大规模智能体系统的核心蓝图。
